# Запуск GlucoDel

Нужны Node.js 24 и npm.

```sh
npm ci
npm run dev:full
```

Откройте адрес Vite в терминале. В разделе «Источники данных» выберите «Открыть локальный архив». Там можно загрузить отдельные CSV для CGM и помпы, а затем добавить запись о еде с временем из выгрузки. Исходное время интерпретируется по часовому поясу в CSV. Интерфейс и отчёт показывают московское время (UTC+3).

Сервер Node.js слушает только loopback. SQLite хранит данные в `.glucodel/workspace.sqlite`. Архив и демо разделены. Публичная сборка на GitHub Pages работает на синтетических данных и хранит правки в браузере. Запустите `npm run dev`, чтобы открыть этот режим локально.

## Подключение Nightscout

Нужен HTTPS-адрес Nightscout, куда приложение участника уже отправляет данные, и выданный владельцем отдельный токен с ролью `readable`. Возьмите адрес без параметров. Настройка токена описана в [документации Nightscout](https://nightscout.github.io/nightscout/admin_tools/#subjects-and-roles).

Создайте в корне GlucoDel локальный файл `.env.local`:

```dotenv
NIGHTSCOUT_URL=https://nightscout.example.org
NIGHTSCOUT_READ_TOKEN=замените-на-токен-чтения
```

Перезапустите `npm run dev:full`. В разделе «Источники данных» откройте «Локальный архив». Там видны время последней успешной синхронизации и время последнего полученного измерения. Можно нажать «Синхронизировать сейчас».

- Первый запрос читает до 14 дней истории; далее GlucoDel проверяет обновления каждые 5 минут, пока запущен локальный сервер. Запросы перекрываются на 48 часов, чтобы подобрать запоздавшие записи. При длительном перерыве подгружается до 14 последних дней.
- Чтение идёт через Nightscout API v1. Импортируются измерения CGM типа `sgv` и записи поддерживаемых типов болюса. В дозу фактической подачи записи Nightscout не включаются. Для подтверждённой подачи используйте CSV помпы. При одинаковом времени измерения CGM архив отдаёт предпочтение CSV.
- Один локальный архив рассчитан на одного человека. Для другого участника используйте отдельную копию проекта с отдельным архивом. Для отключения синхронизации уберите переменные из `.env.local`, перезапустите GlucoDel и отзовите выделенный токен в Nightscout. Ранее сохранённая история остаётся в локальном архиве.
- Токен хранится в локальном файле конфигурации и передаётся только сервером GlucoDel указанному Nightscout по HTTPS. Для источника используйте доверенный адрес. Публичное демо не предоставляет подключение и не получает реальные записи.

## CSV

Файл в UTF-8, до 3 МБ и 50 000 строк. Используйте запятую или точку с запятой, значения без кавычек. Для десятичной запятой разделяйте столбцы точкой с запятой. Примеры обоих шаблонов можно скачать на экране импорта. Эти шаблоны описывают обменный формат GlucoDel. Выгрузку конкретного производителя нужно привести к нему.

**CGM**

```csv
measured_at,glucose_mmol_l
2026-11-16T12:55:00+03:00,6.1
2026-11-16T13:00:00+03:00,6.2
2026-11-16T13:15:00+03:00,7.1
```

Укажите время ISO 8601 с часовым поясом и значения в ммоль/л. Пустое значение означает пропуск. Время получения показания в этом формате отсутствует. На графике разрывы выявляются из расчёта на 5-минутный ряд, с допуском на разницу между замерами до 7,5 минут. При другом интервале такая разметка может отличаться от разметки устройства. Исходные измерения хранятся без изменения времени и значений.

**Инсулиновая помпа**

```csv
event_id,started_at,ended_at,type,actual_units,planned_units,status,mode
001,2026-11-16T12:55:00+03:00,,bolus,2.1,2.1,given,ручной
002,2026-11-16T13:10:00+03:00,,bolus,0.4,0.8,interrupted,ручной
003,2026-11-16T13:25:00+03:00,,bolus,,0.5,cancelled,ручной
```

Используйте постоянный идентификатор события, тип `bolus` или `basal`, статус `given`, `interrupted` или `cancelled`. `actual_units` — фактически поданное количество в единицах, а не скорость в ед./ч. Время окончания, фактический и запланированный объём и режим могут быть пустыми. Пустое фактическое количество отображается как неизвестное. Для отмены план сохраняется отдельно от фактической подачи.

Повторная загрузка тех же данных пропускает дубли. Для CGM ключом служит время измерения, для помпы — идентификатор события. Формат рассчитан на одну историю CGM и одну историю помпы. Конфликт по ключу или неверная строка отклоняют весь файл с сообщением об ошибке.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run test:api
npm run build
npx playwright install chromium
npm run test:e2e
```

Тесты API используют временный SQLite. Playwright проверяет статическую сборку под подпутём, включая ширины 390, 768 и 1440 px. Workflow в GitHub Actions прогоняет проверки на push и pull request. Деплой Pages запускается только после проверок основной ветки.
